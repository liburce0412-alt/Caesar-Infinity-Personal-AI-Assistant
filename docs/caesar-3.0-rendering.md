# Caesar 3.0 自适应渲染

本轮保持共享 SPECTRA 渲染器、三个局部玻璃面板与一颗气泡的预算、原生文字及现有材质。光带宽淡外晕、平行暖带、黑镜上半球、通透下半球与薄彩虹膜的 shader 参数未改；降低采样次数不改变场景时间或光带速度。

## 本地实现

| 模式 / 状态 | 帧率提示上限 | 场景纹理边长比例 |
| --- | --- | --- |
| AUTO 正常；HIGH 正常 | 120 Hz | 0.50 |
| AUTO 省电模式 / MODERATE 热状态 / 持续压力一级 | 60 Hz | 0.42 |
| AUTO SEVERE 热状态 / 持续压力二级 | 30 Hz | 0.34 |
| HIGH 达到 CRITICAL 热状态；显式 LOW | 30 Hz | 0.34 |

这些是渲染预算，不是已达到的实际帧率。显示器选择权仍由系统持有；调度按完整显示周期采样，例如设备保持 90 Hz 时，60 Hz 上限使用稳定 45 Hz。LOW 保留原有静态玻璃降级；AUTO 降档仍保留场景折射与气泡，只降低共享场景纹理分辨率和请求频率。HIGH 保留第三层噪声细节，不因普通省电、普通热状态或帧压力被降为 AUTO；仅 CRITICAL 及以上热状态应用保护预算。

控制器使用现有 Compose 帧时钟间隔、实际 GL 回调完成间隔和 GL 回调区间耗时。连续两个一秒窗口有至少 20% 的帧周期缺失或回调区间耗时超出预算的 80%，AUTO 降一级。此耗时是回调开始到结束的墙钟时间，包含 CPU 提交及可能等待，未按调度拆成纯 CPU 执行时间，也不是 GPU 执行时间。连续八个健康窗口（各类压力不超过 5%、每窗至少八个真实 GL 样本）才恢复一级；省电 / 热状态的下限仍生效。刷新率变更、前后台切换和场景暂停重置样本，恢复后不会把后台间隔判为卡顿，也不会把缺少 GL 样本判为健康。

热状态与省电监听仅在已挂载、已恢复的 Surface 上注册，暂停和卸载时注销。预算调整不更新 Compose 状态；场景 FBO 只在尺寸 / GL 上下文 / 档位变化时重建，光学 pass 仍被裁剪至注册区域；没有新增 View、GL 循环、逐气泡定时器、联网或权限。动态效果关闭继续完全不挂载 GL。

`SpectraRenderPolicyTest` 覆盖省电 / 热边界、持续压力与短暂波动、GL 拥堵与回调成本、延迟逐级恢复、缺少样本、前后台间隔、显式 HIGH / LOW 和 60/90/120 Hz 整周期调度。执行结果由 3.0 总验收记录汇总。

平台 API 依据：[Android PowerManager](https://developer.android.com/reference/android/os/PowerManager)（API 29 起热状态监听；旧设备仍使用省电状态和帧反馈）。

## 已记录的设备结果

2026-10-18，Xiaomi 15 Pro 从 2.2.2 保数据升级到 3.0 后，保存了以下约 18 秒个人页 trace。AUTO 和暖机 HIGH 在采样前通过 XML 确认顶部统计可见；暖机 HIGH 的“高”选项父节点 `selected=true`。完整数值、逐手势超时、温度和复核 SQL 见 [设备性能证据](../artifacts/caesar-3.0-device/performance-notes.md)。

| 样本 | 全段 App Deadline Missed | 应用 FrameTimeline 区间 p99 | 惯性有效间隔 | 惯性实际呈现频率 / 间隔 p99 |
| --- | ---: | ---: | ---: | ---: |
| 2.2.2 基线 | 2 / 543（0.37%） | 21.15 ms | 421 | 119.70 Hz / 8.34 ms |
| 3.0 首次 HIGH | 9 / 312（2.88%） | 26.85 ms | 220 | 120.02 Hz / 8.33 ms |
| 3.0 AUTO，确认顶部 | 5 / 541（0.92%） | 17.65 ms | 422 | 120.02 Hz / 8.33 ms |
| 3.0 暖机 HIGH，确认顶部 | 8 / 541（1.48%） | 17.25 ms | 422 | 120.01 Hz / 8.33 ms |

“惯性”沿用既有 SQL 的松手后 50–1800 ms 窗口，只统计其中有更新的相邻实际呈现间隔。三个候选样本的全部超时都在这个窗口之外：首次 HIGH 为输入期 8 次、松手后前 50 ms 1 次；AUTO 与暖机 HIGH 全在输入期。因此约 120 Hz 表明这些惯性窗口的呈现节奏，不能写成全程稳定 120 fps。应用 FrameTimeline 区间时长也不等于呈现间隔或 GPU 执行时间。[FrameTimeline 口径](https://perfetto.dev/docs/data-sources/frametimeline)

首次 HIGH 的 9 次超时分布在六个手势，不能全部归于首次滚动；该样本最长区间 78.58 ms，暖机 HIGH 最长 21.04 ms，前者极长区间本次未再现。首次 HIGH 的有效滚动量较少，保留为升级后早期体验记录，不用它代替顶部暖机对照。首份 `candidate-auto-profile` 因采集前停在设置区而未纳入配对，排除依据是起点不符，文件仍保留。

AUTO 与暖机 HIGH 的滚动量接近，但只有各一次、温度和注入节奏未完全一致；5 与 8 次超时不证明模式优劣，也没有捕获到 AUTO 降档/恢复日志。它们的 miss 比例均高于较早且较冷的基线，而区间 p99 较低，现有证据不支持宣布“比 2.2.2 更流畅”或“自适应收益已验证”。

GL 回调频率约 119–120 Hz 是提交侧记录，**不表示 GPU 已完成或屏幕已呈现**。另存的基线、首次 HIGH、AUTO 的 SurfaceFlinger GL 图层快照各约 1.04 秒，实际呈现约 120 Hz；基线与 AUTO 快照并不与各自 trace 同步，不能扩展为全段 GL 帧时或 GPU 耗时结论。

各性能样本前后公开 Thermal Status 均为 0，基线电池约 37.6 °C，候选约 39.6–39.7 °C，持续充电。充电与温度仅记录为帧时测量条件。用户已明确耗电不测；本轮不作节电或续航结论，耗电不属于本次验收或发布阻塞项，也无需为此补做断电测试。

AI 页 HIGH 的独立生命周期 trace 已确认后台停止 GL 回调并在返回后恢复。当前文件使用 64 MiB 缓冲与进程快照，无非零覆盖/丢失统计，完整包含预先记录的后台区间；两端各缩进 0.2 秒后的 2.69 秒内 `onDrawFrame=0`，跨边界重叠也为 0；返回标记后 0.2 秒起记录到 706 次回调。首份 8 MiB 环形缓冲样本因后台区间被覆盖而判无效，已由此完整样本替换；没有用缺失区间的零行结果证明停绘，也没有重采个人页性能对照。此结果不证明 GPU 已闲置或所有监听已释放。

## 真实 GL 的隔离预算验证

后续在同一设备运行 debug 专用的12阶段有限时长探针，结果见 `artifacts/caesar-3.0-completion/render-probe.json`。探针使用实际共享渲染器与 GL Surface，读取预算、实际纹理尺寸及 FBO 状态；全部预期降档、逐级恢复和 HIGH 保护阶段通过。24ms 主线程阻塞制造的进程帧压力真实发生；热等级与省电布尔为探针合成输入，和真实系统读值分开记录。没有修改系统温控、系统时间或主动加热手机。

此结果补齐策略到真实渲染器/FBO的接线与恢复验证，不能称为真实系统过热事件、GPU压力、耗电收益或所有页面视觉通过。GL回调及纹理读回仍不是GPU完成时间或屏幕呈现频率。

## 当前证据范围

已覆盖个人页六次纵向手势（三轮往返）的整体卡顿与惯性呈现、HIGH 模式选中状态、上述短 GL 实际呈现快照，以及一次 AI/HIGH 后台停绘与返回恢复。以下行为尚不能由这些样本判定：

- 真实系统省电切换、MODERATE / SEVERE / CRITICAL 热事件的自然触发。12阶段已验证合成热/省电输入及真实进程帧压力的降档/恢复接线，不能将它替代真实热事件；早期性能采样预算日志为空也不单独作通过依据。
- 息屏、对话框覆盖、反复进出页面、动态效果关闭后的完整生命周期表现，以及长对话增量和气泡转场的帧时。
- 浅 / 深色、经典 / 流体与各预算下材质的一致性；静态 LOW 降级需和动态样本分开判断。

本地策略测试、真实GL隔离探针和既有设备呈现片段分别报告，不合并为全场景性能或视觉验收。按用户最新要求收敛，不追加上述完整矩阵或人为真实热事件测试；这些限制不新增为发布硬阻塞。发布状态由总验收记录决定，耗电不测。
