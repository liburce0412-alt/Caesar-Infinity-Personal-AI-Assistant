# 时间分析提示词与 Qwen 视觉接入

> 历史记录。当前截图课表已支持按周多图直接导入，最新行为与验收见 [2026-10-05 验证记录](frontend-timetable-20261005.md)。

## 时间分析不是把原始记录直接交给模型

`CampusAiTaskFactory` 先在 Kotlin 中按今日、本周或本月筛选记录，并生成以下确定性事实：

- `totalMinutes`、`recordCount`、`targetMinutes`、`remainingTargetMinutes` 与 `goalRateBasisPoints`；
- `categoryMinutes` 与 `categoryShareBasisPoints`；
- `dailyMinutes`、`activeDays`、`currentStreakDays`、`longestSessionMinutes`；
- `peakDate` 与 `peakMinutes`；
- `trendDirection`、`trendDeltaAverageMinutes`、前半段和后半段日均分钟；
- 课程冲突及自然语言中能够确定的时长。
- `allowedActionSubjects`：最近记录中真实存在的任务名称白名单，建议只能逐字引用；空列表时只能使用“最重要的任务”等通用名称。
- `suggestedActionPlan`：Kotlin 生成的下一步行动块、块间休息、已覆盖分钟和执行后剩余差距；模型不得自行拟定建议时长。
- `analysisStatements`：Kotlin 根据范围生成的可引用事实句；本地 2B 模型不得从原始字段额外推断休息习惯、效率、成绩或原因。

趋势定义为当前范围内“后半段日均分钟 - 前半段日均分钟”。正数为 `up`，负数为 `down`，相等为 `flat`；只有一天时为 `insufficient_data`。它是学习投入趋势，不代表成绩或效率因果关系。

当前目标预设为今日 240 分钟、本周 1,680 分钟、本月 7,200 分钟。这只是初始默认值；接入用户的 `TimeGoal` 后，应由目标仓库提供，不应让模型猜测个人目标。

## 回复契约

- 首页洞察：两句话；第一句引用事实做分析，第二句给一个包含学习对象与明确时长的立即行动。
- 今日总结：投入与目标差距 → 分类或节奏观察 → 两条包含对象和时长/开始时间的行动。
- 周总结：引用已计算趋势和日均变化 → 目标及主要分类 → 两条下周行动。
- 月总结：投入、目标差距和趋势 → 主要分类与峰值日期 → 两条包含时长或频率的调整。
- 数据不足必须直说；不得重新计算数字、补造课程、推断成绩或把相关性写成因果。2B 模型仍可能违约，因此真机质量集必须专门检查“未授权科目名称”。

`LocalPromptPolicy` 同时要求直接输出答案，不展示思考过程、内部 JSON、系统提示或约束。输出防护会拦截不安全的内部过程文本。

## Qwen3.5-2B 视觉能力如何使用

模型目录已经包含视觉编码器，首个正式场景应是“课程表截图导入”，采用两阶段而不是让模型直接写数据库：

1. 图片选择器读取本机图片，完成方向修正、裁切和尺寸限制；不把原图上传。
2. JNI 将像素数据作为 MNN `MultimodalPrompt` 的图片部分交给本地 Qwen，并要求输出候选课程字段、原文证据和不确定项。
3. Kotlin 对星期、节次、开始/结束时间、周次和字段范围做 schema 校验；冲突仍由 Kotlin 计算。
4. 用户在可编辑预览中逐条确认，确认后才写入 Room；低置信或缺失字段标记“待确认”。
5. LOCAL 模式全程本机；若用户明确切到 DeepSeek，必须再次提示图片与文本将离开设备。

后续可复用在学习笔记图片整理、校园海报的日期地点提取、图表说明与市场商品草稿，但不得用 2B 视觉模型做身份识别、交易风控、账号安全或无人工确认的最终录入。

## 尚未完成的视觉门禁

- JNI 图片入口、取消和视觉实例释放；
- 当前 MNN 3.6.1 arm64 runtime 的视觉编译能力确认；
- 同一张课程表对 ML Kit OCR、Qwen 视觉和组合方案的字段准确率对照；
- 大图缩放、EXIF 旋转、峰值内存、首字时间和五分钟稳定性；
- 飞行模式与网络日志验证；
- 低置信字段的编辑预览 UI。

这些门禁通过前，现有产品文案只能写“本机 OCR 导入”，不能写“Qwen 识图导入”。
